# חיבור המערכת ל-Google: יומן, Gmail ו-Drive

אחרי ההגדרה הזו, כל משתמש באתר לוחץ "חיבור לחשבון Google" ומאשר גישה לחשבון שלו. מכאן הוא רואה במסך **יומן, מייל ו-Drive**:

- **יומן:** האירועים שלו לשבועיים הקרובים, הוספת אירוע חדש (כולל הזמנת משתתפים), הוספת משימה ליומן ביום היעד, והוספת ישיבה מפרוטוקול. בלוח הבקרה מופיע "היומן שלי היום ומחר".
- **Gmail:** המיילים האחרונים בתיבה, חיפוש, שליחת מייל, ויצירת משימה ממייל בלחיצה. שליחת פרוטוקול עם קובץ Word מצורף ישירות מה-Gmail שלו.
- **Drive:** הקבצים האחרונים שלו, חיפוש לפי שם, העלאת קובץ, שמירת פרוטוקולים כ-Word וגיבוי מלא.

**כל משתמש רואה רק את החשבון שלו.** החיבור נשמר בדפדפן של המשתמש בלבד, תחת שם המשתמש שלו באתר, ונמחק כשהוא יוצא מהמערכת. האתר אינו שומר מיילים, אירועים או קבצים בשום מקום.

ההגדרה נעשית פעם אחת, על ידי מנהל המערכת. זמן משוער: כ-15 דקות, ועוד כ-10 דקות לחיבור הקבוע (שלב 7). אין עלות.

## 1. פרויקט ב-Google Cloud

1. נכנסים ל-https://console.cloud.google.com עם חשבון ה-Google של החברה.
2. למעלה, בבחירת הפרויקט › **New project**. שם: `femy-management` › **Create**. (אם כבר הוקם פרויקט Firebase בשם הזה, בוחרים אותו.)

## 2. הפעלת שלושת ה-API

**APIs & Services › Library**. מחפשים כל אחד מהבאים ולוחצים **Enable**:

- **Google Calendar API**
- **Gmail API**
- **Google Drive API**

## 3. מסך ההסכמה (OAuth consent screen)

**APIs & Services › OAuth consent screen** (בממשק החדש: **Google Auth Platform**).

1. **App name:** `פמי הנדסה - מערכת ניהול`. **User support email:** המייל של המנהל.
2. **Audience / User type:**
   - **אם המייל של החברה (femy.co.il) מנוהל ב-Google Workspace:** בוחרים **Internal**. כל העובדים בדומיין יכולים להתחבר, בלי אישור של Google ובלי הודעות אזהרה. זו האפשרות המומלצת.
   - **אחרת:** בוחרים **External**, משאירים במצב **Testing**, ותחת **Test users** מוסיפים את המייל של כל משתמש (עד 100). במצב הזה Google מציגה בחיבור הראשון הודעה שהאפליקציה לא אומתה. לוחצים "המשך".
     **שימו לב:** במצב Testing, Google מבטלת את החיבור הקבוע (שלב 7) אחרי 7 ימים, וצריך להתחבר שוב. כדי שהחיבור יישאר קבוע, עוברים ל-**In production** (**Publish app**). בלי אימות של Google, המשתמשים ימשיכו לראות את הודעת "האפליקציה לא אומתה" בחיבור הראשון, וזה תקין לשימוש פנימי של החברה.
3. **Scopes** (או **Data access › Add or remove scopes**). מוסיפים את אלה:

| הרשאה | למה |
|---|---|
| `.../auth/calendar.events` | הצגת האירועים ביומן והוספת אירועים |
| `.../auth/gmail.readonly` | הצגת המיילים בתיבה |
| `.../auth/gmail.send` | שליחת מייל, רק כשהמשתמש לוחץ ומאשר |
| `.../auth/gmail.compose` | הכנת טיוטת תשובה בשרשור של הפרויקט |
| `.../auth/gmail.modify` | מייל שנקרא באתר (מקטע "מיילים") מסומן כנקרא גם ב-Gmail |
| `.../auth/drive.readonly` | הצגת הקבצים ב-Drive וחיפוש |
| `.../auth/drive.file` | העלאת קבצים ושמירת פרוטוקולים וגיבויים, בתיקייה "פמי הנדסה - מערכת ניהול" |

4. **Save**.

## 4. יצירת OAuth Client ID

1. **APIs & Services › Credentials › Create credentials › OAuth client ID** (או **Google Auth Platform › Clients › Create client**).
2. **Application type:** `Web application`. שם: `femy-web`.
3. **Authorized JavaScript origins** › **Add URI**:
   - `https://femiengineering.github.io`
   - `http://localhost:8000` (רשות, להרצה מקומית)
4. **Authorized redirect URIs:** משאירים ריק.
5. **Create**. מופיע **Client ID** שנראה כך: `123456789-abcdef.apps.googleusercontent.com`. מעתיקים אותו.
6. לחיבור הקבוע (שלב 7) צריך גם את ה-**Client secret** מאותו מסך. **אל תדביקו אותו באף קובץ במאגר.** הוא נכנס רק לשרת, בשלב 7.

## 5. הדבקת ה-Client ID באתר

בגיטהב פותחים את הקובץ [`google-config.js`](../google-config.js) › עיפרון (Edit), ומדביקים בין המירכאות:

```js
window.FEMY_GOOGLE = {
  clientId: '123456789-abcdef.apps.googleusercontent.com',
};
```

**Commit changes**. תוך דקה-שתיים האתר מתעדכן.

ה-Client ID אינו סוד, וזה תקין שהוא במאגר ציבורי: Google מקבלת בקשות איתו רק מהכתובות שהוגדרו בשלב 4.3. ה-Client secret, לעומת זאת, סודי, ולא נכנס לשום קובץ במאגר.

## 6. חיבור של כל משתמש

1. נכנסים לאתר עם המשתמש שלכם.
2. בתפריט: **יומן, מייל ו-Drive** › **חיבור לחשבון Google** (או בהגדרות, "חשבון Google שלי").
3. בוחרים את חשבון ה-Google שלכם ומאשרים את ההרשאות.

**עם החיבור הקבוע (שלב 7):** מאשרים פעם אחת בכל מכשיר, והחיבור נשאר פעיל, בלי חלונות ובלי לחיצות, עד שלוחצים "ניתוק". יציאה מהאתר מנתקת רק את המכשיר הזה, והכניסה הבאה בו דורשת לחיצה אחת בלי לאשר שוב.

**בלי שלב 7:** החיבור תקף כשעה. אחר כך מופיע כפתור **חידוש החיבור**: לחיצה אחת, בלי לאשר שוב את ההרשאות.

לניתוק מלא: בהגדרות › "ניתוק" (מבטל את הגישה בכל המכשירים), או ב-https://myaccount.google.com/permissions.

## 7. חיבור קבוע: שרת Cloudflare Worker (מומלץ)

בלי השלב הזה, החיבור ל-Google מתנתק כל שעה. השלב הזה מקים שרת קטן וחינמי ששומר לכל משתמש מפתח קבוע מ-Google (refresh token), מוצפן, ומחדש ממנו את הגישה ברקע. הקוד נמצא בתיקייה [`worker/`](../worker/).

**עלות:** התוכנית החינמית של Cloudflare (עד 100,000 בקשות ביום). אין צורך בכרטיס אשראי. זמן משוער: כ-10 דקות.

צריך מחשב עם [Node.js](https://nodejs.org) (גרסה 18 ומעלה) ועותק של המאגר.

1. נרשמים בחינם ב-https://dash.cloudflare.com/sign-up.
2. בחלון פקודה (Terminal), בתיקייה `worker` של המאגר:

```bash
npx wrangler login
npx wrangler kv namespace create TOKENS
```

3. הפקודה השנייה מדפיסה `id = "..."`. פותחים את [`worker/wrangler.toml`](../worker/wrangler.toml) ומדביקים:
   - את ה-`id` בשורה `id = ""`.
   - את ה-Client ID (שלב 4) בשורה `GOOGLE_CLIENT_ID = ""`.
4. שומרים את שני הסודות. כל פקודה מבקשת להדביק ערך:

```bash
npx wrangler secret put GOOGLE_CLIENT_SECRET
```
מדביקים את ה-Client secret משלב 4.6.

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
npx wrangler secret put ENC_KEY
```
הפקודה הראשונה מייצרת מפתח הצפנה אקראי. מעתיקים אותו ומדביקים בשנייה. אין צורך לשמור אותו במקום אחר.

5. מפרסמים את השרת:

```bash
npx wrangler deploy
```

בסוף מופיעה כתובת כמו `https://femy-google.<שם-החשבון>.workers.dev`.

6. בגיטהב, בקובץ [`google-config.js`](../google-config.js), מדביקים את הכתובת ב-`tokenServer`:

```js
window.FEMY_GOOGLE = {
  clientId: '123456789-abcdef.apps.googleusercontent.com',
  tokenServer: 'https://femy-google.<שם-החשבון>.workers.dev',
};
```

**Commit changes**. מעכשיו כל משתמש לוחץ "חיבור לחשבון Google" פעם אחת בכל מכשיר.

**מה השרת שומר:** לכל חשבון Google, את המפתח הקבוע שלו, מוצפן. לכל מכשיר, מפתח מכשיר אקראי (רק הגיבוב שלו נשמר). השרת לא שומר מיילים או אירועים. עם שלב 8 הוא שומר גם עותק של גיליון המשימות ושל רשימת הפרוטוקולים (שמות קבצים ותיקיות בלבד, לא את תוכן המסמכים), ומקבל בקשות רק מכתובות האתר שב-`ALLOWED_ORIGINS`.

## 8. סנכרון קבוע מה-Drive, גם בלי חשבון Google מחובר

השרת משלב 7 קורא את ה-Drive בעצמו כל 15 דקות: את רשימת התיקיות והפרוטוקולים בתיקייה **פרויקטים פמי** ואת הגיליון **משימות פמי**. הוא עושה זאת עם החשבון שכבר חובר באתר (המפתח הקבוע שהשרת שומר משלב 7), כך שאין צורך ב-Service Account ואין מה להגדיר ב-Google. האתר מקבל את הנתונים מהשרת בכל מכשיר, גם בלי שום חיבור ל-Google.

1. מחברים פעם אחת חשבון Google באתר (כפתור "חיבור לחשבון Google") עם חשבון שרואה את התיקייה ואת הגיליון. אם כבר חיברתם, אין צורך שוב.
2. בחלון פקודה, בתיקייה `worker` של המאגר (אחרי `git pull`):

```bash
npx wrangler deploy
```

3. בדיקה: בעמוד הפרוטוקולים באתר לוחצים **🔄 סנכרון עכשיו**. אמור להופיע "עודכן עכשיו". אפשר גם לפתוח `https://femy-google.<שם-החשבון>.workers.dev/data/status` מהאתר, או לבדוק ב-Cloudflare: **Workers › femy-google › Logs**.

השרת בוחר לבד את החשבון הראשון שחובר ויכול לפתוח את התיקייה. אם החיבור שלו בוטל ב-Google (שינוי סיסמה, הסרת הרשאה), הסנכרון נרשם ביומן ומחכה. האתר ממשיך לקבל את העותק האחרון, והחיבור הבא באתר מחדש את הסנכרון.

כל הנתונים זמינים גם בבקשה אחת: `GET /api/sync-data` מחזיר את רשימת הפרוטוקולים, את הגיליון (xlsx ב-base64) ואת מצב הסנכרון האחרון.

מזהה התיקייה ומזהה הגיליון רשומים ב-[`worker/wrangler.toml`](../worker/wrangler.toml) (`PROJECTS_FOLDER_ID`, `TASKS_SHEET_ID`). אם מחליפים תיקייה או גיליון, מעדכנים שם ומריצים שוב `npx wrangler deploy`.

(אופציונלי: אם מוגדר הסוד `GOOGLE_SERVICE_ACCOUNT_KEY`, השרת משתמש בו רק כשאין אף חשבון מחובר שעובד.)

**איך זה עובד באתר:** הפרוטוקולים נטענים מהשרת תמיד. המשימות נטענות מהשרת כשאין חשבון Google מחובר במכשיר, וכשיש, ישירות מהגיליון (בלי השהיה של עד 15 דקות). רשימת הפרויקטים לא השתנתה: היא מגיעה מהקובץ `projects/drive-projects.json` ולא דורשת חיבור.

**שימו לב:** השרת מחזיר את הנתונים רק לבקשות מכתובת האתר, אבל זו הגנה מפני אתרים אחרים בדפדפן ולא סיסמה. מי שמכיר את כתובת השרת יכול לקרוא את גיליון המשימות (כולל אנשי הקשר) ואת שמות הפרוטוקולים, בדומה לקבצים שכבר נמצאים במאגר הציבורי.


## בעיות נפוצות

- **"Error 400: redirect_uri_mismatch" או "origin_mismatch":** הכתובת של האתר לא נוספה ב-Authorized JavaScript origins (שלב 4.3). שימו לב: בלי `/` בסוף ובלי `/femy-management`.
- **"Access blocked: app has not completed the Google verification process":** המשתמש לא ברשימת Test users (שלב 3.2).
- **"אין הרשאה" ביומן, במיילים או ב-Drive:** ה-API לא הופעל (שלב 2), או שבחלון של Google לא סומנו כל ההרשאות. מתנתקים בהגדרות ומתחברים שוב, ומסמנים הכול.
- **החלון של Google לא נפתח:** הדפדפן חוסם חלונות קופצים. מאשרים חלונות קופצים לאתר ולוחצים שוב.
- **"עוד שלב אחד: לחצו שוב על חיבור":** קורה פעם אחת אצל מי שהתחבר לפני הפעלת החיבור הקבוע. לוחצים שוב ומאשרים את ההרשאות.
- **"שרת החיבור ל-Google לא זמין":** הכתובת ב-`tokenServer` שגויה, או שהשרת לא פורסם (שלב 7.5).
- **החיבור הקבוע נעלם אחרי שבוע:** האפליקציה במצב Testing (ראו שלב 3.2).
- **`origin_not_allowed`:** כתובת האתר לא ברשימת `ALLOWED_ORIGINS` בקובץ `worker/wrangler.toml`. מתקנים ומריצים שוב `npx wrangler deploy`.
